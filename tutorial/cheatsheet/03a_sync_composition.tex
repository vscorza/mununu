\cheatheader{03a --- Synchronous Composition}{Lock-Step Parallel Execution}

\begin{multicols}{3}
\footnotesize

%% ---- COLUMN 1 ----

\begin{cheatbox}{Syntax}
Compose two or more automata in lock-step:
\begin{lstlisting}[style=ctxdsl]
composition {
    synchronous pipeline {
        members [Producer, Consumer];
    }
}
\end{lstlisting}
The result \code{pipeline} is a new automaton you can reference in formulas and controllers just like any other.
\end{cheatbox}

\begin{cheatbox}{Semantics}
Both automata step \textbf{simultaneously} every cycle:
\begin{itemize}
\item \textbf{Shared labels} (same name in both automata) \emph{must} fire together --- they synchronize.
\item \textbf{Non-shared labels} combine freely: each side picks one of its own transitions independently.
\item A composed step is a pair of transitions, one from each member.
\end{itemize}

\smallskip
Example: \code{transfer} is shared; \code{produce}, \code{p\_skip}, \code{consume}, \code{c\_skip} are private.
\end{cheatbox}

\begin{tipbox}{State Space}
The composed state space is the \emph{product} of component state counts.  E.g., Producer(2) $\times$ Consumer(2) = 4 composed states.  Keep components small to avoid explosion.
\end{tipbox}

%% ---- COLUMN 2 ----

\begin{cheatbox}{Skip Labels}
Each automaton needs its own skip/idle label:
\begin{lstlisting}[style=ctxdsl]
// Producer
transition Empty -> Empty
    on label p_skip;
transition DataReady -> DataReady
    on label p_skip;

// Consumer
transition Waiting -> Waiting
    on label c_skip;
transition Processing -> Processing
    on label c_skip;
\end{lstlisting}
Add a self-loop with the skip label on \emph{every} state of the automaton.
\end{cheatbox}

\begin{warnbox}{Shared Idle Trap}
Do \textbf{NOT} use the same idle label in both automata:
\begin{lstlisting}[style=ctxdsl]
// WRONG — both use "idle"
transition A -> A on label idle; // in Automaton1
transition X -> X on label idle; // in Automaton2
\end{lstlisting}
Because \code{idle} is shared, both are forced to idle \emph{together} --- neither can act independently.  Always use distinct names (\code{p\_skip}, \code{c\_skip}).
\end{warnbox}

%% ---- COLUMN 3 ----

\begin{cheatbox}{Formulas on Compositions}
Use \emph{structural} formulas (no state-name predicates) on composed systems:
\begin{lstlisting}[style=ctxdsl]
// Safety over composition
formula safety_invariant {
    over pipeline;
    body = nu X. ([] X);
}

// No deadlocks: every state has
// at least one successor
formula no_deadlock {
    over pipeline;
    body = nu X. ((<> true) && ([] X));
}
\end{lstlisting}
State-name predicates (\code{Empty}, \code{Waiting}) only work on individual members, not on the composition.
\end{cheatbox}

\begin{cheatbox}{Per-Component Properties}
Check properties on individual automata separately:
\begin{lstlisting}[style=ctxdsl]
formula producer_can_produce {
    over Producer;
    body = mu X. (DataReady || <> X);
}
formula consumer_processes {
    over Consumer;
    body = mu X. (Processing || <> X);
}
\end{lstlisting}
\end{cheatbox}

\begin{tipbox}{Complete Example}
\begin{lstlisting}[style=ctxdsl]
context sync_producer_consumer {
    automata {
        automaton Producer { ... }
        automaton Consumer { ... }
    }
    composition {
        synchronous pipeline {
            members [Producer, Consumer];
        }
    }
    mu_formulas { ... }
}
\end{lstlisting}
\end{tipbox}

\end{tipbox}
