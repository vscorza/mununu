\begin{cheatbox}{Multi-Label Syntax}
Fire multiple signals in a single transition:
\begin{lstlisting}[style=ctxdsl]
transitions {
    // Write: 3 signals at once
    transition Idle -> WritePhase
        on label addr_valid,
           label data_valid,
           label ctrl_write;

    // Read: 2 signals at once
    transition Idle -> ReadPhase
        on label addr_valid,
           label ctrl_read;

    // Single-label (still valid)
    transition WritePhase -> Ack
        on label ack;
}
\end{lstlisting}
Comma-separate labels after \code{on}.  Order does not matter.
\end{cheatbox}

\begin{cheatbox}{When to Use Multi-Label}
Multi-label transitions model scenarios where several signals assert \emph{simultaneously} in one clock cycle:
\begin{itemize}
\item Hardware buses (AXI, SPI, PCIe)
\item Grouped control signals
\item Atomic compound actions
\end{itemize}
If events happen \emph{sequentially}, use separate single-label transitions instead.
\end{cheatbox}

%% ---- COLUMN 2 ----

\begin{cheatbox}{Single vs.\ Multi-Label}
\begin{tabularx}{\linewidth}{@{}lXX@{}}
\toprule
 & \textbf{Single} & \textbf{Multi} \\
\midrule
Signals/step & 1 & $\geq 1$ \\
Syntax & \code{on label a;} & \code{on label a, label b;} \\
Use case & Sequential protocols & Parallel buses \\
Composition & Label syncs individually & All labels in set must sync \\
\bottomrule
\end{tabularx}
\end{cheatbox}

\begin{tipbox}{Example: AXI-Like Bus}
Model a bus where address, data, and control assert together:
\begin{lstlisting}[style=ctxdsl]
// AXI write = addr + data + write ctrl
transition Idle -> WritePhase
    on label addr_valid,
       label data_valid,
       label ctrl_write;

// AXI read = addr + read ctrl
transition Idle -> ReadPhase
    on label addr_valid,
       label ctrl_read;
\end{lstlisting}
The label \code{addr\_valid} appears in both transitions but with different companions --- this models two distinct bus operations sharing an address phase.
\end{tipbox}

\begin{cheatbox}{Other Transition Types}
Besides labeled transitions, CTXDSL supports:

\smallskip
\textbf{Epsilon transitions} --- silent/internal steps:
\begin{lstlisting}[style=ctxdsl]
transition A -> B on epsilon;
\end{lstlisting}

\smallskip
\textbf{Guarded transitions} --- conditions + variable effects:
\begin{lstlisting}[style=ctxdsl]
transition A -> B
    guard (x > 0)
    effects { x = x - 1; };
\end{lstlisting}
Guards are covered in later tutorials (state variables \& abstraction).
\end{cheatbox}

\begin{tipbox}{Composition with Multi-Labels}
In \emph{synchronous} composition, a multi-label transition synchronizes on \textbf{all} of its labels that are shared with the other automaton.  Non-shared labels in the set combine freely.

\smallskip
Rule of thumb: if \emph{any} label in the set is shared, the partner must be able to participate on that label in the same step.
\end{tipbox}

\begin{cheatbox}{Formulas on Multi-Label Systems}
Labeled modalities work with individual labels:
\begin{lstlisting}[style=ctxdsl]
// Does an addr_valid transition exist?
< labels = { addr_valid } > true

// All ack transitions end safely
[ labels = { ack } ] Safe
\end{lstlisting}
A multi-label transition \code{on a, b} is matched by modalities filtering on \code{a} \textbf{or} \code{b}.
\end{cheatbox}
