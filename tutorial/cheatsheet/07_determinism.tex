\cheatheader{07 --- Determinism}{Deterministic vs Non-Deterministic Models}

\begin{multicols}{3}
\footnotesize

%% ---- COLUMN 1 ----

\begin{cheatbox}{Deterministic}
Each (state, label) pair has \textbf{exactly one} target state.
\begin{itemize}
  \item Given a state $s$ and a label $a$, at most one transition $s \xrightarrow{a} s'$ exists.
  \item Behavior is fully predictable: the same input sequence always produces the same execution.
  \item Verification is simpler --- box and diamond modalities coincide.
\end{itemize}
\begin{lstlisting}[style=ctxdsl]
// Deterministic: one target per label
transition Locked -> Unlocked
    on label unlock;
transition Locked -> Strike1
    on label bad_code;
\end{lstlisting}
\end{cheatbox}

\begin{cheatbox}{Non-Deterministic}
The same (state, label) pair can have \textbf{multiple} target states.
\begin{itemize}
  \item $s \xrightarrow{a} s_1$ and $s \xrightarrow{a} s_2$ with $s_1 \neq s_2$.
  \item Models uncertainty, environment choices, or abstraction.
  \item Execution is not uniquely determined by input alone.
\end{itemize}
\begin{lstlisting}[style=ctxdsl]
// Non-deterministic: two targets for 'req'
transition Idle -> Granted
    on label req;
transition Idle -> Denied
    on label req;
\end{lstlisting}
\end{cheatbox}

%% ---- COLUMN 2 ----

\begin{cheatbox}{Box vs Diamond}
\textbf{Box} (\code{[~] phi}) --- universal: \emph{all} successors satisfy $\varphi$.

\textbf{Diamond} (\code{<> phi}) --- existential: \emph{some} successor satisfies $\varphi$.

\smallskip
\begin{tabularx}{\linewidth}{@{}lX@{}}
\toprule
\textbf{Syntax} & \textbf{Meaning} \\
\midrule
\code{[ labels = \{a\} ] phi} & All $a$-transitions lead to $\varphi$ \\
\code{< labels = \{a\} > phi} & Some $a$-transition leads to $\varphi$ \\
\bottomrule
\end{tabularx}

\smallskip
\textbf{Deterministic systems:} box $=$ diamond (only one successor), so both modalities are equivalent.

\textbf{Non-deterministic systems:} box is strictly stronger than diamond.
\begin{lstlisting}[style=ctxdsl]
// Box: ALL req-transitions reach Safe
[ labels = {req} ] Safe

// Diamond: SOME req-transition reaches Safe
< labels = {req} > Safe
\end{lstlisting}

If there are two $\mathit{req}$-successors and only one is \code{Safe}, diamond holds but box fails.
\end{cheatbox}

%% ---- COLUMN 3 ----

\begin{cheatbox}{Impact on Verification}
Non-determinism affects formal verification in several ways:
\begin{enumerate}[leftmargin=*]
  \item \textbf{Box modality may fail} --- a single ``bad'' successor is enough to violate \code{[] phi}.
  \item \textbf{Diamond still holds} --- only one ``good'' successor is needed for \code{<> phi}.
  \item \textbf{Larger effective state space} --- branching increases the number of paths to explore.
  \item \textbf{Controller synthesis} --- the controller must handle \emph{all} non-deterministic branches the environment may take.
\end{enumerate}
\end{cheatbox}

\begin{tipbox}{When to Use Non-Determinism}
\begin{itemize}
  \item \textbf{Environment uncertainty} --- the system cannot predict which branch the environment will choose.
  \item \textbf{Protocol variations} --- multiple valid responses to the same stimulus.
  \item \textbf{Abstraction} --- collapsing implementation details introduces non-determinism.
  \item \textbf{Under-specification} --- leaving design choices open.
\end{itemize}
\end{tipbox}

\begin{warnbox}{Pitfall}
Confusing \textbf{box} (all paths) with \textbf{diamond} (some path) when the system is non-deterministic.  A property verified with diamond does \emph{not} guarantee it holds on every execution --- use box for universal guarantees.
\end{warnbox}

\begin{warnbox}{Skolem Paradigm}
The controller chooses a \textbf{label} (action), not a specific transition.
Nondeterministic outcomes (same label, multiple targets) are always
\textbf{adversarial} --- ALL outcomes must satisfy, regardless of
controllability.

\code{mu X. (Good || <> X)} at a state with \code{risky -> Good} and
\code{risky -> Bad}: \textbf{fails} (Bad might happen).

\code{mu X. (Good || Bad || <> X)}: \textbf{succeeds} (both outcomes OK).

{\scriptsize Ref: Milner (1989) \textit{Communication and Concurrency}.}
\end{warnbox}
