### Surprises / dead-ends

- *2026-05-06:* The cargo dead-code linter flagged `entry_capacity_hint` and `set_capacity_hint` as unread once I converted the `ensure_*_capacity` helpers to no-ops. Fully removed both fields + the no-op helpers + their call sites for a clean ablation.
- *2026-05-06:* The 3 capacity-related unit tests (`grow_capacity_zero_current`, `grow_capacity_small_values`, `grow_capacity_large_values`) at `clts/mod.rs:2805-2837` still pass — they only assert `clts.state_count()` matches expectations, not that growth happens at any particular rate. Names are now misleading; rename is an optional follow-up.
- *2026-05-06:* The 20% wrapper's stated rationale (per inline comment: *"keep peak memory under control"*) is empirically wrong. Vec doubling has the same peak in practice with fewer reallocations. Hypothesis-driven measurement beats hand-tuned growth strategies — at least on this workload class.
